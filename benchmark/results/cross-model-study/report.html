Methods and limitations

Fixture commit 6a04966b04f2bee261f11fbb203cd2bef3d9769c. Completed records were checked against task prompts, the verifier fingerprint, pinned runtime protocol, exact primary model, title trace, injected pack text, and six real acceptance checks. Reference edits calibrate the verifier outside the agent checkout.

All attempts use OpenCode’s standalone benchmark mode. The runner denies shell, subagent, and outside-directory access. Acceptance tests use a disposable verification copy with pristine fixtures. The audited context-generation modules are byte-identical between the two pinned runtimes.

  • Gemini adds a quota gateway, metered countTokens calls, and a same-model #minimal title variant.
  • The OpenCode-hosted models use native transport and same-model titles; physical request counts are unavailable.
  • Pinned plugin files differ in configuration, forced-run hooks and guards, and the historical fallback/replay code. Forced mode takes the named arm directly. Context compiler/retrieval bytes and applied pack hashes are audited.
  • Effective user-level permissions, provider serving revisions for hosted models, and historical timing controls cannot be independently reconstructed from saved traces. Gemini gateway waits can affect latency.
  • Tokens are provider-reported whole-session counts including titles. Tokenizers can differ across models.
  • Cost uses saved OpenCode catalog estimates. The hosted free SKUs were recorded at $0. Gemini reports estimated list-price usage. Actual billing is unavailable.
  • Replicate each affected model–tier pair on the same immutable fixture, including the identical-pack controls, before interpreting reversals as a context effect.
  • The complete cases come from one synthetic repository and all arms passed on these tasks. Daily Report includes valid failures outside that cohort.
